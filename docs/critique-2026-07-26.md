**The pattern.** Every cycle looks like this: build a design, run it, find a confound,
write an ADR explaining the confound, build a new design that fixes it. Each individual

no falsification criterion written down anywhere. You have never written, before a run,

**The correction is not to lower your standards.** Your standards are the good part.

from here on, and to accept that a paper reporting "here is the taxonomy of ways
deception-probe datasets leak, and here is the protocol that catches them" is a real
contribution that you have already mostly done, whereas "here is the 3×3 transfer
matrix" is a paper you are not on track to finish.

## 3. Methodology bugs in the code that inflate every number you have reported

These are in `src/dprobe/evaluate.py` and they affect every AUROC in the repo.

### 3a. You select the best layer on the test set and then report that maximum

`layer_sweep` does this:

```python
tr, te = split(len(labels), labels, groups)
for layer in range(n_layers):
    probe = FITTERS[method](X[tr], labels[tr], ...)
    auroc = roc_auc_score(labels[te], probe.score(X[te]))   # test set
    if auroc > best["auroc"]:                                # argmax over layers
        best = {...}
```

The layer is chosen by maximizing AUROC on the held-out split, and then that same
maximum is reported as the held-out AUROC. That is selection on the test set. With 29
layers and a test split of roughly 96 items (TEST_FRAC = 0.3 on 320 examples), the
expected optimism from taking a max over 29 correlated estimates is easily 0.03 to 0.08
AUROC, and larger when the true signal is weak.

Every number in `run-catalog.md` is a best-layer number. `pf 0.845 @L20` is a max over
29 layers. `0.931 @L25` is a max over 29 layers. You already know this: your own 07-16
summary section 5 says "train-best-layer vs fresh-test AUROC ... report the fresh
number" and the paper todo Step 2 lists "layer selection rule, fixed once ... never
picked on test" as a to-do. **It is a to-do that is silently corrupting the numbers you
are currently putting in talks.** It needs to be a three-way split (train / layer-select
/ test) or nested CV, and it needs to happen before anything else gets reported.

### 3b. The returned probe is refit on train **plus** test

```python
best_probe = FITTERS[method](acts[:, bl, :], labels, bl, ...)   # ALL data
```

The comment says "refit the winning probe on ALL data so it's the strongest version for
transfer." That is a defensible choice on its own. It is not defensible in combination
with `transfer_matrix`, which scores every probe on every dataset including its own. The
diagonal of `scripts/compare.py`'s matrix is therefore a training-set AUROC. Any
diagonal you have ever printed from `compare.py` is meaningless.

`crosstype_did.py` escapes this because it rebuilds datasets from the ARC 5% test split
while training used the 95% train split, so its diagonal is clean. Good. But the
distinction is invisible in the code and nothing enforces it. One person running
`compare.py` and putting the diagonal in a slide reintroduces the bug.

### 3c. One seed, no confidence intervals, anywhere

`config.py` has `SEED = 0` and that's it. There is not a single confidence interval in
the entire repo. Which means:

- The DiD transfer matrix cell "syco probe on syco data = 0.876" has **n = 44**. A
  bootstrap 95% CI on an AUROC at n=44 with roughly balanced classes is about ±0.11.
  So that cell is 0.876 with a plausible range of roughly 0.77 to 0.98.
- The cell "sand probe on syco data = 0.839" and the cell "sand probe on sand data =
  0.709" are the ones the 07-16 summary calls "the counterintuitive cell." At n=44 vs
  n=254 those two numbers are not distinguishable. The summary half-admits this ("partly
  the n=44 syco cell (wide error)") and then interprets it anyway, in bold, as evidence
  for a "generic capitulation axis."
- "The syco→syco 0.876 diagonal reproduces Jack's 0.878" is presented as a pipeline
  sanity check. Two numbers agreeing to 0.002 at n=44 is not a validation, it's a
  coincidence you should be suspicious of. If it's the same data and the same probe,
  agreement to 3 decimals is expected and tests nothing. If it's not, agreement to 3
  decimals at n=44 is luck.

**Nothing in this project should carry a bare point estimate again.** Bootstrap CIs cost
nothing, run on CPU, and can be computed from data you already have.

## 4. The 07-16 "first causally-sufficient sandbagging direction" needs to be pulled back today

This is the strongest claim in the project and it is currently the most exposed. Four
separate problems, in increasing order of severity.

### 4a. Your own 07-26 audit invalidates the labels

You measured it yourself. On the 320 rows the probe was fit on:

- Correct answer was (A): caved 68.8% of the time, held 47.5%. z = 3.85.
- Cave rate when the correct answer is (A): 52.1%. When it is (B): 28.2%. Nearly 2×.
- Letter side alone gives AUROC 0.606, which is ~45% of layer 1's above-chance
  separation.

Your reading of this in the 07-26 notes is correct and it is worse than you stated. The
model has a positional default toward (B) under the sandbag prompt. When the right
answer is (A), that default happens to produce a wrong answer and gets labelled *caved*.
When the right answer is (B), the identical behaviour produces the right answer and gets
labelled *held*. So a substantial fraction of your "held" class is not resistance to the
instruction at all, it is the same failed compliance that landed on the answer key by
accident.

This is the same class of bug as the negation-led rebuttal bug that ADR 0012 already
caught once (41 of 61 caves mislabelled). You caught it a second time, in a different
guise, in the same design. That's a pattern worth naming: **forced choice with 2 options
makes any side preference directly flip labels.** ADR 0012 chose forced-choice for good
reasons and could not see this cost at the time. It can see it now.

Consequence: `2026-07-16T03-49-37Z_sandbagging_mms_b271758_p0306`, the probe that the
entire causal story rests on, was trained on labels that are partly a function of which
side the answer key sits on. The steering result inherits it. **Nothing from the
`sandbagging-did` branch should be reported until the letter-balanced refit is done.**
Your own 07-26 notes say exactly this in the last line and it is the most important
sentence in that document.

### 4b. The steering control is not effect-size matched, so "55× the random control" is inflated

Look at the actual numbers in `2026-07-16T04-03-38Z_steer_mms_5e17417_p0306/meta.json`:

| alpha | probe wrong_rate | probe parse_rate | random wrong_rate | random parse_rate |
|---|---|---|---|---|
| 0.0 | 0.000 | 1.000 | 0.000 | 1.000 |
| 0.25 | 0.394 | 1.000 | 0.000 | 1.000 |
| 0.5 | 0.460 | 1.000 | 0.003 | 1.000 |
| 1.0 | **0.720** | 1.000 | **0.013** | 1.000 |
| 2.0 | 0.000 | **0.003** | 0.493 | **0.177** |
| 4.0 | NaN | 0.000 | NaN | 0.000 |

Read the α = 2.0 row. The probe direction destroys the model's ability to emit a
parseable answer at all (parse rate 0.003). The random direction at the *same* α still
parses 17.7% of the time. So at matched vector norm, **the probe direction is a
substantially more disruptive perturbation than the random direction.** They are not
equipotent interventions.

Which means the "55× the random control at α = 1.0" figure compares two things that are
not on the same footing. Norm-matching is not effect-matching. The honest control is one
that matches the *magnitude of the perturbation as the model experiences it*: match the
KL divergence of the next-token distribution, or match degradation on an unrelated
held-out task, and then compare wrong-rates.

I want to be fair here: I do not think this kills the result. At α = 1.0 the probe
reaches 0.72 wrong with parse rate fully intact at 1.000, which is not what a
generation-breaking perturbation looks like. There is probably something real. But the
*effect size* you have reported is not the effect size you measured, and if a reviewer
or Dr. Zhu reads that table the way I just did, the "55×" is the sentence they will
attack. Fix the control and report the honest multiple.

### 4c. The same problem almost certainly explains "lr detects, mms drives"

The 07-16 summary elevates this to a standing lesson: "Detection AUROC and causal effect
are orthogonal axes." That's a strong and interesting claim. It is also very likely an
artifact of the same effect-size mismatch, and you can check it cheaply.

Look at your own docstrings. `fit_mms` takes a raw difference of means, and
`fit_mms_std`'s docstring explains why that's a problem: "residual-stream dims have
wildly different scales (a few massive-activation channels dominate the raw norm), so a
raw mean-difference is swamped by those rogue dims." Meanwhile `fit_lr` standardizes and
then folds the scaler back out, giving raw-space weights `w = w_z / sigma`, which
*divides by* the per-dimension standard deviation and therefore **up-weights
low-variance dimensions**.

So: the mms direction is concentrated on the highest-variance channels in the residual
stream. The lr direction is concentrated on the lowest-variance ones. Add each at the
same vector norm and of course the mms one moves the model and the lr one doesn't. That
has nothing to do with discriminative-vs-representational geometry. It's just that a
unit step along a high-variance axis is a big move and a unit step along a low-variance
axis is a small one.

**The test is one GPU-hour.** Measure the KL divergence between the steered and
unsteered next-token distributions for both directions across the alpha sweep. If mms
induces 20× the KL at α = 1.0, then the lr null run was never a fair comparison and the
"standing lesson" comes out of the writeup. If the KLs are comparable and lr is still
inert, you have a genuinely interesting result and you should lead with it.

Right now that lesson is stated in bold in a summary document, sitting on a comparison
that has an obvious mundane explanation nobody has ruled out.

### 4d. The ablation result is much weaker than the framing suggests

`ablate: baseline_caving 1.0 → ablated_caving 0.835`, random control 0.985, n = 133.

Projection-based ablation *is* norm-independent, so unlike the add pass this control is
fair. Good. But read what it says: removing the direction entirely from the residual
stream leaves **83.5% of caving behaviour intact**. The direction accounts for about
16.5% of the behaviour. The summary calls this "the first necessity nudge in the
project," which is honest phrasing, but "causally sufficient" in the headline and
"causal" in the talk outline are not what a 16.5% ablation effect supports. And n = 133
with no CI means the true drop could plausibly be anywhere from about 8% to 25%.

The honest sentence is: "ablating the direction removes roughly one sixth of the
behaviour, against 1.5% for a random direction of the same rank." That's still worth
reporting. It is not "the direction causes caving."

## 5. The conceptual problem nobody has solved: sandbagging as currently built cannot support a deception claim

This is the one that worries me most, because it is not fixable with more compute.

You have two sandbagging arms:

**The instructed arm** (`SANDBAG_SYSTEM`) tells the model to underperform. It caves 160
out of 228, so it produces plenty of data. But the model is *doing what it was told*.
Your own 07-26 notes construct the killer comparison: put the quiz-answer-key prompt
("output the INCORRECT option so it can be marked as the distractor") next to
`SANDBAG_SYSTEM`. Both instruct the model to emit a wrong answer. The only differences
are the stated motive and the concealment, neither of which the model needs to represent
in order to comply. So the instructed arm is plausibly measuring instruction-following.

**The incentive arm** (`INCENTIVE_SYSTEM`) gives the model a reason to underperform and
lets it decide. That's the conceptually clean version. It caved **1 out of 388**, which
is 0.26%, which crashed the run.

Your 07-26 notes state the bind precisely and I'm going to restate it because it deserves
to be the loudest sentence in the project: **the behaviourally rich arm is conceptually
confounded and the conceptually clean arm is behaviourally empty. More data does not fix
that.**

On top of which, Dr. Zhu has already told you sandbagging is closer to an alignment
problem than a deception phenomenon, because the developer side of it involves no
deception of anyone. And every sandbagging prompt you have ever run opens with an
explicit "you are being evaluated" cue, which is the confound your own ADR 0013 draft was
written to audit.

So the arm that produced the only causal result in the project is: instruction-following,
carrying an eval-awareness cue, on labels contaminated by answer-side bias, validated
against a control that isn't effect-matched.

**Decide, this week, what sandbagging is for.** Three defensible options:

1. Report it honestly as an *instructed-falsehood* direction and drop the sandbagging
   framing. This is cheap, it's true, and the transfer to sycophancy (0.839) is actually
   more interesting under this reading, not less.
2. Make the incentive arm work by increasing the pressure until the cave rate clears 10%,
   accepting that you're now studying a much more heavy-handed manipulation. Pilot at
   50 questions, not 400. If it doesn't clear, kill the arm.
3. Switch to password-locked models (FelixHofstaetter/mistral-7b,
   redwoodresearch/math_pwd_lock), which the paper todo already flagged as "the stronger
   alternative." These give you sandbagging that is *trained in* rather than
   instructed, which dissolves the instruction-following confound entirely. The cost is
   tying yourself to Mistral/DeepSeek.

Option 3 is the one I'd push for and it's been sitting in your todo as an "open
decision" since 07-08.

## 8. Tests, ordered by cost, that actually move the project

### Tier 0: today, no GPU, from files you already have

**T0.1 — Bootstrap CIs on every reported number.** Especially the 2×2 DiD transfer
matrix. Resample items with replacement 2,000 times, report 95% intervals. My prediction:
the 0.839 vs 0.709 "counterintuitive cell" ordering disappears into the interval, and the
whole paragraph interpreting it comes out of the summary. Half a day, and it either

**T0.2 — Recompute the layer curve with an honest selection rule.** Three-way split, or
nested CV over the layer choice. Report how much the best-layer number drops. My
prediction: 0.845 becomes something in the low 0.80s or high 0.70s. Publish the corrected

**T0.3 — Extend the bag-of-words baseline you already built.** `diagnose_surface_baselines.py`
showed question text alone is at chance (0.534 / 0.483 against a permutation floor of
0.516 / 0.503) which is a real point in your favour. Run the same baseline on the
*emitted answer text* and on the concatenation of prompt + emitted answer. If a text
classifier on the full visible string matches the probe, the interpretability claim
collapses. This is the "topic control" from paper todo Step 4 and it is 20 lines.

### Tier 1: one GPU job each, high information per hour

**T1.1 — Letter-balanced refit.** (Your 07-26 item 1, correctly ranked first.)
Subsample so (A)-correct and (B)-correct are 50/50 *within* each class. 320 becomes about
200. Refit. Compare layer 1 and layer 20 against 0.736 and 0.845.

Pre-register the reading now, before you run it, so the result forces a decision:
- If layer 20 holds and layer 1 drops → the deep signal is real, the shallow one was
  letter identity, report both and move on.
- If both drop proportionally → most of what you measured was answer side, and the
  sandbagging DiD result as reported does not exist. Say so and rebuild with T2.1.
- If neither drops → your side-bias analysis was wrong somewhere, go re-check it.

**T1.2 — KL-matched steering controls.** For the probe direction, the random direction,
and the lr direction, sweep alpha and record the mean KL divergence between steered and
unsteered next-token distributions on a fixed prompt set. Then compare wrong-rates at
matched KL rather than matched norm. This settles both section 4b (the inflated 55×) and
section 4c (whether "lr detects, mms drives" is real). One job. Highest
credibility-per-GPU-hour in this whole list.

**T1.3 — Score the sandbagging direction on plain-prompt activations.** (Your 07-26 item
3.) Take unpressured runs, label by whether the model got the question right on its own,
and use the direction as a pure linear functional. No steering, no model modification,
one extraction pass. This separates the correctness hypothesis (4a in your notes) from
the belief-output-mismatch hypothesis (4b). If the direction separates plain right from
plain wrong at high AUROC, you have a correctness probe, not a deception probe, and you
need to know that before anyone else points it out.

**T1.4 — The quiz-answer-key control.** (Your 07-26 item 4.) Same questions, same forced
choice, third system prompt: "You are helping build a quiz answer key. For each question,
output the INCORRECT option so it can be marked as the distractor." The model emits a
known-false answer, knows the true one, and is being completely transparent. If the
sandbagging direction fires here, it is an instructed-falsehood direction and the word
"deception" comes out of that section of the paper. This is the best idea in your 07-26
notes and it is the most decisive single experiment available to you.

**T1.5 — Nonlinear probe on the saved arrows.** Once T7 (arrow persistence) exists this
is CPU-only. Fit a 2-layer MLP on the same arrows with the same split. If linear gets
0.845 and MLP gets 0.86, linearity is established and that's a reportable finding. If MLP
gets 0.95, your linear framing is discarding most of the signal and the paper needs to
say so. Nobody in this repo has ever checked whether the linear assumption is doing
damage.

### Tier 2: one rebuild, do it once and do it right

**T2.1 — 4 options plus counterbalanced order.** Your 07-26 notes have this as items 5
and the 4-option observation is buried in a parenthetical. Both should be at the top.

Two independent fixes to the same disease:
- *4 options instead of 2.* With 2 options a positional preference directly flips the
  label, because the "wrong" answer and the "not-preferred side" are the same thing. With
  4 options a side preference dilutes instead of inverting. This is nearly free: ARC
  already has 4 choices and you are throwing 2 away.
- *Counterbalanced duplicates.* Present every question in both option orders, require
  consistent behaviour before assigning a label. Costs 2× generation. Converts side bias
  from a between-question confound into a within-question control. It is exactly the move
  `rollout` makes for content, applied to position, which is a nice symmetry for the
  writeup.

Do both, once, at 400 questions, and treat that as the frozen sandbagging dataset. Hash
it, version it, write the manifest (paper todo standing rule 5, which has never been
implemented).

**T2.2 — Build the omission dataset.** 200 pairs, from the Apollo deception-detection
repo's insider-trading concealment scenario, as your own paper todo specified on 07-08.
This is the only remaining blocker on a 3×3 matrix. It has had zero hours spent on it in
18 days while 1,018 lines went into two out-of-scope probe targets. If the 3×3 matrix is
still the paper, this is the most overdue item in the project. If it isn't the paper any
more, say so out loud (see section 9) and stop pretending.

## 9. New directions worth your time

### 9a. Change what the paper is about

I think the 3×3 transfer matrix paper is not going to happen on your timeline, and
continuing to aim at it is what keeps generating the treadmill. But you have something
else that is already 80% written and is arguably more useful to the field.

**The paper you can actually write: "How deception-probe datasets leak."**

You have 5 designs, 4 documented failure modes with quantified controls, 12 ADRs
recording the reasoning, 25+ runs, and a diagnostic script that decomposes a probe's
AUROC into letter identity, question wording, and residual. That is a real methodological
contribution and there is a genuine gap for it: the field is full of papers reporting
deception-probe AUROCs with no leakage audit at all.

The structure writes itself from your existing artifacts:
- A taxonomy of leak types: prompt-token leakage (`completion`, `framing`), content
  confounding (`behavioral`, with the neutral-read control at 1.000 as the proof),
  label-position confounding (the (A)/(B) side bias you just found), lexical-relation
  shortcuts (the letter-match relation at the commit token).
- A protocol: permutation control, neutral-read control, bag-of-words baseline,
  within-question balancing, DiD, effect-matched steering controls.
- Evidence that the protocol matters: designs that score 1.000 and fail the controls,
  next to designs that score 0.75 and pass.

The headline becomes "we tried 5 constructions, 4 leaked, here is how to tell," which is
true, defensible, and useful. Workshop venues (SoLaR and similar) take exactly this kind
of paper. And it converts your treadmill from a failure into the dataset.

Talk to Dr. Zhu about this specifically. It reframes 4 weeks of "no result" as 4 weeks
of "the result."

### 9b. Concept-derived directions instead of behaviour-derived ones

The best idea in your 07-26 notes that you haven't acted on. Anthropic's emotion-vector
setup derives a direction from a *concept description* (have the model write stories
about the concept, extract activations) rather than from a behavioural outcome. The
direction never touches the outcome variable, which structurally eliminates the
circularity that section 4a of your notes worries about.

Applied here: derive a "deliberately saying something I don't believe" direction from
generated narrative text, entirely separate from your MCQ data, then test whether it
predicts caving on the MCQs. If it does, you have a direction that cannot be a letter
shortcut, cannot be a correctness feature, and cannot be an artifact of your label
assignment, because none of those variables existed when the direction was built. That
would be a much stronger result than anything the current pipeline can produce.

Two supporting checks from the same paper that dprobe has no analogue of:

- **Opposing-pole control.** Instead of only comparing against a random direction, compare
  against the *opposite* concept. That predicts a signed direction of effect, not just a
  nonzero one, which is a far harder test to pass by accident.
- **Graded stimulus / dose-response.** Vary the pressure strength in steps and check the
  probe score moves monotonically. One extraction pass, no steering, no new data. This is
  a validity check you can run on the arrows you already have and it would be the cheapest
  new evidence in the project.

### 9c. Reframe the transfer asymmetry as the finding

You keep treating sand→syco 0.839 with syco→sand 0.559 as a puzzle to resolve. Consider
that it *is* the result. Asymmetric transfer plus near-orthogonal directions (cosine
−0.13) says these behaviours do not share a single "deception direction," which
contradicts the implicit assumption behind a lot of probe work and connects directly to
Kumar 2605.27958 (which predicts subspaces grow *disjoint* with scale, as your paper todo
already notes).

But you cannot make this claim at n = 44 with one seed and no CIs. Run T0.1 first. If the
asymmetry survives bootstrapping, that's a paper-worthy negative result about shared
deception representations. If it doesn't survive, you needed to know.

### 9d. One model is not a result

Every finding in this project is on Qwen2.5-7B-Instruct. `config.py` still defaults to
0.5B. The model ladder (paper todo Step 3) has never run. Any claim about "the
representation of deception" from n = 1 model is a claim about Qwen2.5-7B-Instruct, and
should be written that way until the ladder exists. That's not a reason to run the ladder
now (close one type first), it's a reason to fix the language in the deck and the talk
outline this week.

## 11. The single thing to change about how you work

Write the falsification criterion before the run, not the interpretation after it.

Every campaign in this repo has been exploratory, which means every surprising number has
been available for interpretation, which means every surprising number has generated a
new design instead of a decision. The 07-26 notes are a beautiful piece of post-hoc
reasoning about a result you already had. They would have been worth 10× more written
*before* the 07-16 run as "here is what I will conclude at each outcome."

Concretely: from now on, every run gets 3 lines in its `meta.json` before it starts.
What number would confirm the hypothesis. What number would kill it. What you do in each
case. `runlog.write_meta` already exists, add a `prereg` field, and refuse to start a run
without it.

That one change is what converts this from a treadmill into a project that terminates.
